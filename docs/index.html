Converse about a pull request, then request changes on it

The journey a blind developer needs from start to finish: open a real pull request, ask what changed in a file, hear the exact numbered source lines, spell one out symbol by symbol, correct a misheard command, and submit a Request changes review bound to the commit that was reviewed. Every turn posts to POST /api/review/turn and reads back what it understood before it acts, so a wrong hearing can be interrupted. Reading a public pull request is a live, unauthenticated GitHub call. The review write is dry-run by default: the server re-reads the head commit, records the exact request it would send, and sends nothing unless it runs with VOLCAN_GITHUB_WRITE=1 and a token, and the outcome panel says which of the two happened.

Keyboard map and the accessibility contract

This page is the product's shop window, so it holds itself to the standard the product argues for. tests/e2e/test_html_structure.py fails the build when any promise below stops being true of this file.
